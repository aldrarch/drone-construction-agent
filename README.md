# AI-агент мониторинга строительства ИЖС

Локальное MVP-приложение, которое получает фотографии строительного объекта с дрона и предварительно оценивает стадию строительства индивидуального жилого дома (ИЖС).

Основные шаги:
1. Пользователь загружает фотографии объекта.
2. Приложение проверяет изображения.
3. AI-модель анализирует каждую фотографию.
4. Модель определяет предполагаемую стадию строительства.
5. Приложение проверяет GPS-метаданные, если они доступны.
6. Система сравнивает определённую стадию с ожидаемой.
7. Формируется предварительная оценка риска.
8. Создаётся структурированный JSON-отчёт.
9. Результаты показываются в веб-интерфейсе.

Приложение работает локально на Windows. Все вычисления происходят на вашем компьютере.

## Назначение

Приложение помогает быстро сориентироваться по стадии строительства по нескольким фотографиям. Оно не является юридическим, техническим или банковским заключением и не принимает автоматических кредитных решений.

## Подготовка окружения

Создайте виртуальное окружение в папке проекта:

```powershell
cd drone-construction-agent
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Если PowerShell не разрешает выполнение скриптов, выполните:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

## Установка зависимостей

```powershell
pip install -r requirements.txt
```

PyTorch устанавливается из `requirements.txt`. Если у вас нет совместимой CUDA-сборки, убедитесь, что используется CPU-вариант PyTorch.

Приложение автоматически выбирает CUDA при доступности и переходит на CPU, если CUDA недоступна. batch_size равен 1, модель используется в режиме `model.eval()` с `torch.inference_mode()`.

## Переключение модели в будущем

1. Добавьте новую реализацию модели в пакет `models/`.
2. Обновите `config.py`:
   - `MODEL_TYPE = "custom"`
3. Добавьте ветку в `models/model_factory.py`.

Приложение, GPS-сервис, анализ, отчёты и интерфейс не должны требовать переписывания, если новая модель реализует `model_interface.py.ConstructionModel` и возвращает `PredictionResult`.

## Модель

Сейчас используется CLIP ViT-B/32 (`openai/clip-vit-base-patch32`) в режиме zero-shot классификации.

Сравнение идёт с тремя текстовыми группами:
- STAGE_0 — строительство не начато или только фундамент.
- STAGE_50 — строительство в процессе.
- STAGE_100 — строительство завершено.

Промпты на английском языке.

Модель возвращает:
- предсказанный класс;
- оценки сходства с каждым классом;
- разницу между первым и вторым результатом;
- показатель уверенности;
- флаг необходимости ручной проверки.

## GPS

Приложение пытается прочитать GPS из EXIF. Если координаты объекта указаны вручную, считается расстояние. Доступны статусы:
- GPS_FOUND
- GPS_NOT_AVAILABLE
- GPS_MATCH
- GPS_MISMATCH

Порог расстояния настраивается в `config.py` через `GPS_DISTANCE_THRESHOLD_KM`.

GPS EXIF — это только проверка согласованности метаданных. Она не подтверждает подлинность фотографии, дату или отсутствие подмены координат.

## Ограничения CLIP

- CLIP — универсальная модель, а не специализированная модель оценки строительства.
- Оценки сходства не являются откалиброванными вероятностями.
- Результат не заменяет.inspectцию человека.
- Если модель не может уверенно определить стадию, результат содержит флаг ручной проверки.

## Безопасность и надёжность

- Не выдаёт фиктивные предсказания за результаты AI.
- Не скрывает ошибки модели.
- Если модель не загрузилась, показывает понятную ошибку.
- Если GPS отсутствует, явно указывает это.
- Не сохраняет фотографии без необходимости.
- Не отправляет фотографии на сторонние серверы.
- Все вычисления локальные.
- Не делает автоматических выводов о выдаче/отказе в кредите.
- Не называет результат юридическим или техническим заключением.

## Известные ограничения MVP

- Модель общего назначения, а не специализированная.
- Нет обучения собственной модели в этом MVP.
- GPS проверяется только по EXIF.
- Пока нет поддержки формата MRK.
- Отчёт содержит предварительную оценку, а не итоговое решение.
